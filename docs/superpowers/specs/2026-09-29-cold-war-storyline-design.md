# Cold War narrative chart (xkcd 657 style) — plan

## Context

The user is reading Odd Arne Westad, *The Cold War: A World History* (epub at
`~/Downloads/The Cold War_ A World History - Odd Arne Westad.epub`) and wants an
interactive visualization in the style of xkcd 657 "Movie Narrative Charts":
x = time, each line a "character", lines bunch together when they share a
scene, shaded blobs mark where they are. Purpose: a **whole-book overview** of
Westad's account (not generic Cold War history), explorable and shareable,
hosted publicly on GitHub Pages.

Repo `/Users/wouter/.superset/projects/cold-war-visualization` is empty (one
initial commit, no remote). `gh` is logged in as `woutervanranst`; Python 3.14
and Node 25 are available.

## Data model — `data/coldwar.json`

```jsonc
{
  "meta":     { "title": "...", "author": "Odd Arne Westad", "generated": "2026-..." },
  "chapters": [{ "n": 0, "title": "World Making", "pages": [1, 18], "span": [1890, 2017] }, ...],   // n=0 intro, 1–22, 23 conclusion
  "bands":    [{ "id": "west", "label": "The West", "order": 0 }, ...],   // ordered top→bottom
  "regions":  [{ "id": "americas", "label": "Americas" }, ...],            // ≤ 8, drives line colour
  "countries":[{ "id": "cn", "name": "China", "region": "east-asia",
                 "alignment": [{ "from": "1949-10", "band": "east", "ref": {"ch": 9, "p": 237}, "note": "..." }, ...],
                 "parent": null, "mergeInto": null,            // e.g. "gdr": parent "de"; "vn-s": mergeInto "vn" 1975-04
                 "end": null, "chapters": [1, 5, 9, 15, ...] }],
  "leaders":  [{ "id": "mao", "name": "Mao Zedong", "country": "cn", "seat": "cn-top", "role": "Party chairman",
                 "start": "1949-10", "end": "1976-09", "dateSource": "book|general", "chapters": [...] }],
  "events":   [{ "id": "yalta-1945", "date": "1945-02", "title": "Yalta conference", "rank": 1,   // 1–3 visibility tier
                 "kind": "summit|war|crisis|treaty|revolution|split|independence|collapse",
                 "countries": ["us","su","uk"], "leaders": ["fdr","stalin","churchill"],
                 "note": "paraphrase ≤35 words", "refs": [{ "ch": 2, "p": 58 }] }]
}
```
- `band` values (top→bottom, final order confirmed by the build script's band-order score):
  `west` · `axis` (1930s–45) · `colonized` · `nonaligned` · `indep-communist` (Yugoslavia after
  1948, China 1960–72, Albania…) · `east` (from 1917). Bands carry era labels
  (`"labels": [{"from": 1890, "text": "Great powers"}, {"from": 1917, "text": "Capitalist West"}]`),
  so pre-1917 Russia sits among the great powers and its 1917 move into `east` shows the
  revolution as the first split.
- `chapters` on countries and leaders is computed from the index links (chapter lens).
- Dates are `YYYY` or `YYYY-MM`. Leader tenure dates the book doesn't state are filled
  from general knowledge and flagged `dateSource: "general"`.

## Data pipeline (Phase A)

1. **Extract** — `tools/extract_epub.py <epub>` → `work/text/ch00.txt … ch23.txt`
   (plain text, `[p.261]` markers), `work/index.json` (term → subentries → [{ch, page}]),
   and `work/chapters.json` (titles, page ranges; merged into `data/coldwar.json` by the build).
2. **Roster** — rank index entries by page count; I pick ~40 countries/movements and
   ~50 leaders (heads of state/government/party who drive the narrative), assign each
   country a region (≤ 8) and each leader a `seat`. Minor states the book treats collectively
   may become one group line. Saved as `work/roster.json`; I show the user the list before
   extraction.
3. **Per-chapter extraction** — parallel subagents (superpowers:dispatching-parallel-agents,
   ~6 agents × 4 chapters). Each gets the roster, the schema above and its chapter text, and
   writes `work/extract/chNN.json`: alignment changes, leader tenures, events (with page refs,
   paraphrased notes, participants by roster id; unknown entities go to a `candidates` list).
4. **Build & validate** — `tools/build_data.py`: merge, dedupe events (same kind + participants
   within ±1 month), resolve alignment timelines per country, attach index-derived `chapters`,
   then fail on: unknown ids, bad dates, ref pages outside the cited chapter's range, overlapping
   alignment segments, notes > 35 words, 8-word overlap with book text; warns on leaders with no
   events and on more than ~35 simultaneous country lines. Drops alignment flips shorter than ~2 years unless
   flagged `keep`. Scores the band order (total band-distance of all moves) and reports whether
   swapping adjacent bands would reduce it. Prints a per-chapter and per-decade coverage table so
   gaps are visible.
5. **Review pass** — I read the merged timeline per country/leader against the book for
   obvious errors, then commit `data/coldwar.json`.

## The page — `index.html` (Phase B)

Sections inside the single module script, in order: `config` → `data load/normalise`
→ `scales` → `layout` (pure: data + view + filter → per-line piecewise y) → `render`
→ `interactions` → `boot`.

**Chrome**: title in xkcd hand ("THE COLD WAR, AS TOLD BY WESTAD"), a control row above the
chart — `[Countries | Leaders]` segmented toggle · chapter lens `<select>` (0–23) ·
search box with suggestions · "reset zoom" · "list" (opens the events list drawer).
Footer: book credit, font credit, "notes are my paraphrase" disclaimer.

**Axes**: piecewise x scale `domain [1890, 1945, 1991, 2017] → range [0, .15W, .9W, W]`
with visible "squeeze" marks at the break points; year ticks adapt to zoom.

**Layout** (pure function, run once per view/filter, target < 20 ms; ~200 lines)
1. *Frames*: union of change dates for the view (alignment changes; leader start/end),
   month-rounded. Countries with `parent` branch out of the parent's y (E. Germany from Germany);
   `mergeInto` lines fold into the partner (Vietnam 1975, Germany 1990); leaders with the same
   `seat` (successive US presidents) share one track.
2. *Ordering*: bands contiguous in fixed order; initial in-band order by (region, id) so same-hue
   lines form ribbons; 4 rounds of forward/backward barycenter sweeps (stable sort). A line
   entering a band is keyed by its previous y → parent → previous holder of its seat → region.
   Same-date transitions keep their relative order (decolonisation ≈ one parallel ribbon).
3. *Compaction*: per-frame stacking with a smoothing solve — minimise
   `Σ(y_i,f − y_i,f+1)² + λ Σ(y_i,f − T_i,f)²` (λ≈0.05, T = centred plain stack) subject to
   neighbour gaps ≥ lineGap in-band / bandGap between bands. Gauss–Seidel over frames, each frame
   solved exactly by isotonic regression (PAV) after subtracting cumulative gaps; 40 alternating
   sweeps. Bands swell and shrink like xkcd blobs; lines move in coordinated parallel shifts.
4. *Straightening*: snap moves < 0.6·lineGap back to the old y where constraints allow; round to
   0.5 px; re-run 2–4 once ordering by y.
5. *Band envelopes*: per frame min/max member y ± 6 px; an empty band tapers to zero at the
   midpoint of its neighbours.

**Rendering** (SVG, re-rendered on rAF during zoom)
- Zoomed x scale = `base.copy().range(base.range().map(t.applyX, t))` (not `rescaleX`, which
  distorts piecewise breaks); ticks computed per visible segment.
- A line's y at screen-x = `y₀ + Σ Δy_b · smoothstep((x − x_b)/w_b + ½)` with
  `w_b = clamp(0.8|Δy|, 16, 90)` px, so overlapping transitions blend. Sample every 6 px across
  viewport ±100 px, plus 8 samples inside each transition; `curveLinear`.
- *Hand-drawn wobble baked into points*, not an SVG filter: seeded 1-D value noise, ~80 px
  on-screen wavelength, blended across zoom octaves so it stays attached to the data
  (amplitude ≈1.2 px lines, ≈2 px blobs). Blobs share the same sample grid.
- *Hit-testing*: one transparent overlay; on pointermove evaluate every line's y(x) and pick the
  nearest within 6 px (12 px touch).
- *Meetings (leaders view)*: participants bend into the **inter-band gutter** nearest their
  barycenter (never on top of non-participants), ordered by base y, spaced
  `min(3, (bandGap−10)/(n−1))` px; ±4 px plateau with smoothstep ramps `clamp(0.5|Δy|,12,60)` px.
  Events carry `rank` 1–3: rank 1 always pinches, rank 2 from 3× zoom, rank 3 from 8×; greedy
  acceptance skips a pinch if a participant already has one within 2δ or the gutter is taken;
  a repeat meeting of the same group within 2δ+20 px becomes one plateau (Yalta→Potsdam);
  skipped events render as dots on participant lines. Countries view shows events as dots only.
- *Labels*: on-line text, 13 px xkcd Script with background-colour halo (`paint-order: stroke`).
  Candidates: line start, each landing in a new band, sticky left-edge label, repeat every
  ~700 px; greedy placement by priority (pinned > search hit > rank > start > landing > sticky)
  against a collision grid, sliding along flat stretches, else dropped. Re-placed on zoom end
  and throttled (~100 ms) during zoom; widths measured after `document.fonts.load`.
- *View toggle*: line layer fades out/in (200 ms each), band blobs tween. Filtering seeds
  ordering from the full layout, then tweens each line's y.
- *Sizes*: lineGap 10 px (min 7), bandGap 28 px, stroke 2.25 px (3.5 pinned); chart fills the
  viewport (`100svh`, no page scroll fighting d3-zoom), height fit by shrinking lineGap.
  Axis breaks at 1945/1991 drawn as visible squeeze marks; zoom scales the compressed eras too.

**Interactions**
- *Hover*: line → highlight + tooltip (name, span, alignment history). Event marker → tooltip
  (date, title, note, "Ch. 12 · p. 318"), participants highlighted.
- *Click*: pin a line's highlight (others dim to ~15%); click background to clear.
- *Zoom & pan*: x-only `d3.zoom` (wheel, drag, pinch), `scaleExtent [1, 60]`,
  `translateExtent` = chart width, re-render on rAF; reset button; hovering a transition shows
  a tick at its exact date (transitions are centred on their dates, so they start early when
  zoomed out).
- *Chapter lens*: highlights events citing that chapter and entities whose index entries
  point into it; shades the chapter's time span on the axis; "zoom to chapter" link.
- *Search/filter*: type-ahead over countries/leaders/events → highlight; "show only
  selected" chips re-run layout on the subset.
- *Events list drawer*: sortable list of all events with notes + refs, filtered by current
  lens/search — doubles as the accessible table view.

**Colour & a11y** (per the dataviz skill): line colour = region, fixed order, validated
with the dataviz skill's `scripts/validate_palette.js` in light and dark mode; bands are
pale tints with in-chart labels; names are direct labels so identity never rests on
colour; dark mode via `prefers-color-scheme` with its own validated steps; keyboard
focus for event markers; list drawer as table view.
